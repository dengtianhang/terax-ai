## BUG-001：PowerShell Tab 补全错误

- 状态：已验证
- 现象：按 `Tab` 时无法正确接受灰色历史预测，曾错误打开命令补全菜单或补全到文件名。
- 原因：PSReadLine 的 `Tab` 曾绑定为 `MenuComplete`，与历史预测接受逻辑冲突。
- 修复：保留 `History` + `InlineView`，将 `Tab` 绑定为 `AcceptSuggestion`。
- 验证：灰色历史预测可由 `Tab` 接受；Terax dev 重启后保持单实例。
## BUG-002：设置弹框多屏定位与层级

- 状态：已验证
- 优先级：P1
- 现象：设置弹框在不同 DPI 和分辨率显示器上位置偏移；曾错误全局置顶，切换其他软件后仍覆盖在最上层。
- 原因：窗口尺寸与显示器工作区使用了不同 DPI 坐标空间；设置窗口同时启用了全局 `always_on_top`。
- 修复：根据主窗口所属显示器和窗口缩放比例换算窗口尺寸；移除全局置顶；保留设置页内模态、`Esc` 关闭和 Debug 版 DevTools 坐标日志。
- 验证：一屏、二屏均居中；切换其他软件后设置窗口不再全局置顶；`cargo check` 通过并完成 dev 重启。


## BUG-003：设置页面自动打开调试窗口

- 状态：已验证
- 优先级：P2
- 现象：每次打开设置页面时自动出现 DevTools，非调试场景干扰正常使用。
- 原因：open_settings_window 在 debug 构建中主动调用 window.open_devtools()。
- 修复：移除设置窗口打开流程中的自动 DevTools 调用；需要调试时手动开启。
- 验证：设置页面可正常打开，DevTools 不再自动出现。

## BUG-004：新窗口打开后白屏

- 状态：待验证
- 优先级：P1
- 现象：从最近目录选择“新窗口打开”后，新窗口显示白屏。
- 原因：Windows 下在同步 Tauri command 中调用 `WebviewWindowBuilder::build()`，阻塞新 WebView 初始化。
- 修复：将 `open_workspace_window` 改为异步 command。
- 验证：重新打开最近目录的新窗口后，应正常显示 Terax 界面。

## BUG-005：新窗口目录、窗口状态与显示器不正确

- 状态：待验证
- 优先级：P1
- 现象：主窗口全屏时，新窗口变为小窗口；新窗口未显示所选目录；新窗口位置未跟随主窗口所在屏幕。
- 原因：新窗口目录读取后先被全局 `workspaceCurrentDir` 覆盖，随后又被 `adoptWorkspaceEnv` 改为用户 Home。
- 修复：优先使用窗口专属目录；通过窗口 label 识别新窗口；新窗口禁止回退全局目录，并在环境恢复后保留传入目录；复制主窗口位置、尺寸和最大化状态。
- 验证：主窗口全屏及多屏场景下，新窗口继承显示状态并打开所选目录。

## BUG-006：非最大化窗口重启后错误恢复为最大化

- 状态：待验证
- 优先级：P1
- 现象：主窗口改为普通窗口后，强制重启时仍恢复为最大化。
- 原因：窗口状态插件主要在 Tauri `Exit` 时保存；强杀进程不会触发该事件。
- 修复：主窗口移动、缩放、关闭请求时立即保存窗口状态。
- 验证：普通窗口状态保存后重启，仍恢复为普通窗口及对应尺寸位置。

## BUG-007：最大化还原后普通窗口尺寸不是上次尺寸

- 状态：待验证
- 优先级：P1
- 现象：主窗口最大化重启后点击还原，普通窗口尺寸与最大化前不一致。

- 验证：最大化前记录的普通窗口尺寸在重启并还原后保持不变。

## BUG-008：最大化还原后窗口位置未居中

## BUG-009：区块 Ctrl+[ / Ctrl+] 无法切换区域

- 状态：已修复，待用户验证
- 优先级：P1
- 现象：区块完成分区后，按 `Ctrl+[` / `Ctrl+]` 无法切换当前区域。
- 原因：部分 Windows 键盘布局会改写 `KeyboardEvent.key`，快捷键匹配未使用括号按键的物理 `code`。
- 修复：快捷键匹配统一回退到物理按键码，确保 `BracketLeft` / `BracketRight` 可识别。
- 验证：新增快捷键匹配回归测试；已在区块中验证区域焦点切换。

## BUG-010：区块活动区域不明显

## BUG-011：Terax 普通终端未显示 Claude 颜色

- 状态：已修复，待用户验证
- 优先级：P1
- 现象：同一版本 Claude Code 在 CMD/Windows Terminal 中显示颜色，在 Terax 普通终端中显示黑白。
- 原因：Terax 开发环境继承了 `NO_COLOR=1`，PTY 同步继承后，Claude Code 主动关闭 ANSI 颜色。
- 修复：Terax PTY 清除 `NO_COLOR`，设置 `TERM_PROGRAM=Terax`，Windows 设置 `ConEmuANSI=ON`，保留 `TERM=xterm-256color` 和 `COLORTERM=truecolor`。
- 验证：已增加 PTY 环境变量回归测试；需在 Terax 普通终端重新启动 Claude Code 验证颜色。

## BUG-014：安装版无法正常预览本地图片

- 状态：已修复，待用户验证
- 优先级：P1
- 现象：在其他机器安装 Terax 后，访问本地图片无法正常展示。
- 原因：`convertFileSrc()` 生成 `http://asset.localhost/...`，但 CSP 仅允许 `https://asset.localhost`，导致 asset 图片请求被 WebView2 拦截。
- 修复：CSP 补充允许 `http://asset.localhost`；目录图片同时保留 IPC → `data:` URL 回退。视频、音频、PDF 保持原有 Blob URL。
- 验证：需在安装版中打开 PNG、JPG、GIF、WEBP、SVG 等图片确认展示。

## BUG-015：浅色主题下 Codex 输入区黑底黑字

- 状态：已修复，待用户验证
- 优先级：P1
- 现象：浅色主题运行 Codex TUI 时，输入区使用黑色背景，输入文字几乎不可见。
- 原因：浅色主题把 ANSI `black` 映射为深黑色；Codex 输入区使用 ANSI 黑色背景，导致输入区变成黑底。
- 修复：终端 PTY 注入 `TERM_PROGRAM_BACKGROUND=light` 与 `COLORFGBG=0;15`，让 Codex 原生识别浅色背景并绘制浅色输入区；最低对比度保持为 `4.5`。
- 验证：浅色主题进入 Codex，确认输入区文字清晰；普通终端、深色主题无回归。

## BUG-016：Claude/Codex CLI 中 `Ctrl+V` 无法粘贴

- 状态：已修复，待用户验证
- 优先级：P1
- 复现条件：Windows 终端运行 Claude Code 或 Codex CLI，使用 `Ctrl+V` 粘贴文本。
- 实际现象：`Ctrl+V` 未触发剪贴板粘贴。
- 期望行为：`Ctrl+V`、`Ctrl+Shift+V` 都能将剪贴板文本粘贴到终端。
- 影响范围：Windows Terax 终端及终端分区。
- 原因：仅注册 `Ctrl+Shift+V` 为粘贴快捷键，`Ctrl+V` 被当作终端输入发送。
- 修复：Windows 下同时拦截 `Ctrl+V` 和 `Ctrl+Shift+V`，读取系统剪贴板后写入当前终端。
- 验证：需在 Claude Code、Codex CLI、普通 PowerShell 中分别验证两种粘贴快捷键。

## BUG-017：终端粘贴触发浏览器权限提示

- 状态：已修复，待用户验证
- 优先级：P1
- 复现条件：Windows Terax 终端使用 `Ctrl+V` 或 `Ctrl+Shift+V` 粘贴。
- 实际现象：弹出剪贴板“允许/阻止”权限提示。
- 期望行为：终端粘贴直接执行，不弹出浏览器权限提示。
- 影响范围：Windows Terax 终端及终端分区。
- 原因：Windows 使用 `navigator.clipboard.readText()`，触发 WebView2 剪贴板权限机制。
- 修复：Windows、macOS、Linux 统一优先使用 Tauri 原生 `clipboard-manager`，Web Clipboard 仅作为兜底。
- 验证：需在 Windows Claude Code、Codex CLI、PowerShell 中验证两种粘贴快捷键无权限弹窗。
